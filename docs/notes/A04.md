# A04 CSRF boundary walkthrough
Integration requires an explicit HTTPS origin, framework key provider and verified identity resolver.
Default Program exposes no API001 route; tests mount a separate explicit fixture host.
Middleware checks transport/profile and verified session before CSRF, then scope afterwards.
Every unsafe request needs one exact Origin and X-CSRF-TOKEN, including PUT/PATCH/DELETE.
Framework antiforgery validates the cookie/token pair bound to the current identity.
Missing, duplicate, cross-origin or stale-identity tokens fail with the safe error envelope.
GET /api/v1/auth/csrf returns only requestToken, without body/query or session writes.
A private middleware marker prevents unguarded route mapping from minting a token.
Cookies are HttpOnly/Secure/SameSite Strict/host-only; responses use no-store.
A05 owns JWT issuance/expiry; A06 must supply real session/account verification without idle renewal.
Test-only identity headers and ephemeral keys are fixtures, never production defaults.
Operator production profile/keys and real resolver remain prerequisites for runtime activation.
