# A02 bootstrap walkthrough
The operator supplies an explicit DbContext, finite deadlines and a regular password in RAM.
The caller opens SERIALIZABLE and owns commit or rollback of the whole operation.
The repository checks operator rights and holds EC:ADMINSET plus role/account range locks.
The service accepts only the fixed seven role codes and checks the Admin set.
Any existing Admin blocks recreation; locked or disabled accounts remain unchanged.
Only a first creation hashes the secret with P08, adds missing roles and writes Admin.
Mandatory SYSTEM.ADMIN.BOOTSTRAP audit shares the same transaction and has no actor yet.
Its projection contains roleId/status/mustChangePassword, without credentials or contact data.
Any write, audit failure or cancellation requires caller rollback of every change.
SQL fixtures generated test secrets only in RAM and rolled back all seven-role accounts.
The runtime role cannot bootstrap; this code is not called at startup or through an API.
No real Admin was provisioned; production operator context and secret remain deferred.
